# 队伍共游与可选主持

默认“队伍共游”中，每个人都是玩家。创建者另有房间管理能力，不需要负责替其他人点剧情、操控敌人或充当DM。四个固定角色全部共享操作；席位认领用于区分身份。任何队员都能操作轮到的角色，单人可以完成整局；角色的原认领者关闭页面不会造成回合等待。敌人继续由规则自动行动。

所有队员可以选预设剧情、旅行、休整、撤退、最后见证结局。没有投票或队长机制，也没有把在线人数当作推进前置。商量之后提交：服务器以当前修订为准，第一条合法行动立即执行；同修订的其他提交被拒并刷新，不能自动重试同一个意图。一般剧情不可撤回，除非管理者明确读取自己保存的槽位。

房间管理者可以发布/载入地图、自制遭遇、保存/读取命名槽位、导出状态、建立可选文件智能体。这些权力不包含任意改生命、资源、NPC关系或剧情旗标。普通玩家即使伪造请求中的role/canManage/roomMode，服务端也不会采用。管理者不在时，普通队员仍可继续全部常规游戏；管理操作等待原管理席位恢复，不会把权力自动转给最后一个在线的人。

建桌改选“真人主持”则保留原有规则：主持推进剧情、旅行与管理，普通玩家只控制自己认领角色。该模式保留专人主持带团的方式；敌人依旧自动，脚本外自由自然语言裁判不在本次功能内。模式在建桌时确定，不由客户端、剧情选项或存档槽位改变。

断线重连时先恢复本机席位，再取服务端新状态。旧修订请求拒绝；不确定是否执行的同ID可重新提交，跨读档或重启也只算一次。确认409后，重新查看场景，由玩家重新决定是否以新ID提交。退出浏览器不回滚已生效选择。创建者的管理凭据保留在其自己的浏览器存储，不进入邀请链接；若管理凭据丢失，不提供任何玩家自动接管的绕过。

游戏行动每次自动写房间并保留前一份恢复文件。命名存档由管理者操作，只保存游戏状态；读档不改席位、管理权、房间模式或请求账本，并继续增加修订号。新版独立目录不读取旧版私有data。兼容测试使用构造的旧格式副本，旧无mode房间恢复为hosted；旧槽位的游戏数据可以恢复，但不会带来任何角色升权。

文件玩家在共游桌同样能操作队伍与预设剧情，在主持桌只能操作其角色。DM始终可选，由管理者创建；没有DM文件夹或API连接不影响核心游戏。API仅有受约束动作适配层，无密钥或实际付费调用。默认127.0.0.1，跨设备联机仍未测；真实浏览器操作与真人整场体验以独立验收范围为准。
